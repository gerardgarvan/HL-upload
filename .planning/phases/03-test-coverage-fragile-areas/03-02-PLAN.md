**Tests to implement (use pytest.mark.parametrize for ALL edge case tests):**

**1. test_date_format_regex_matching:**
- Test regex patterns match expected formats
- Parametrize: format x valid/invalid strings
- Cases:
  - DATE9_RE: "01JAN2020" (match), "1JAN2020" (no match - needs 2-digit day), "01Jan2020" (match - case insensitive)
  - DATETIME_RE: "01JAN2020:00:00:00" (match), "01JAN2020" (no match - needs time)
  - YYYYMMDD_RE: "20200101" (match), "2020010" (no match - needs 8 digits), "202001011" (no match - too many)
- Use ids=["date9_valid", "date9_short_day", ...]

**2. test_detect_date_columns_null_handling:**
- Test detection skips all-null columns
- Cases:
  - Column with all None → not detected as date
  - Column with all "" (empty string) → not detected as date
  - Column with 50% null, 50% valid dates → detected (only non-null values counted)

**3. test_detect_date_columns_format_detection:**
- Test detection identifies correct SAS format
- Parametrize: date_strings x expected_format
- Cases:
  - ["01JAN2020", "15FEB2020", "31DEC2020"] → "%d%b%Y" (DATE9)
  - ["01JAN2020:00:00:00", "15FEB2020:14:30:00"] → "%d%b%Y:%H:%M:%S" (DATETIME)
  - ["20200101", "20200215", "20201231"] → "%Y%m%d" (YYYYMMDD)
- Use research example from 03-RESEARCH.md "Testing Date Parsing Edge Cases"

**4. test_detect_date_columns_mixed_formats (AUDIT-002):**
- Test detection with mixed formats in same column (30%/50% threshold testing)
- Cases:
  - 70% DATE9 + 30% YYYYMMDD → should detect DATE9 (dominant format)
  - 50% DATE9 + 50% YYYYMMDD → should detect DATE9 (first format tested)
  - 60% invalid + 40% DATE9 → should NOT detect (below 50% value-only threshold)
- Document threshold logic in test docstrings
- Add comment: "AUDIT-002: Validate thresholds (30% name+value, 50% value-only) against real data"

**5. test_convert_date_column_boundary_dates (AUDIT-018):**
- Test conversion handles boundary dates correctly
- Cases:
  - "01JAN1900" → date(1900, 1, 1) (PCORnet minimum, masked births)
  - "29FEB2020" → date(2020, 2, 29) (leap year)
  - "31DEC2026" → date(2026, 12, 31) (near MAX_DATE boundary)
  - "01JAN2100" → should parse but flag in validate_date_range
- Add comment: "AUDIT-018: 1900-01-01 births may be masked values, not legitimate"

**6. test_convert_date_column_invalid_handling:**
- Test conversion keeps column as string when >10% parse failures
- Cases:
  - 90% valid DATE9, 10% invalid → should convert (at threshold)
  - 89% valid DATE9, 11% invalid → should keep as string (exceeds threshold)
  - 100% invalid → should keep as string
- Verify action in returned stats dict: stats["action"] == "converted" vs "kept_as_string"

**7. test_convert_date_column_nulls_preserved:**
- Test conversion preserves existing nulls (doesn't count as parse failure)
- Cases:
  - ["01JAN2020", None, "15FEB2020"] → all parse, null preserved, new_nulls=0
  - ["01JAN2020", "invalid", "15FEB2020"] → 1 parse failure, new_nulls=1
- Verify stats dict: stats["new_nulls"] only counts values that became null

**8. test_validate_date_range_plausibility:**
- Test plausibility bounds (MIN_DATE=1900-01-01, MAX_DATE=2026-12-31)
- Cases:
  - date(1900, 1, 1) → within range (valid)
  - date(1899, 12, 31) → outside range (flagged)
  - date(2026, 12, 31) → within range (valid)
  - date(2027, 1, 1) → outside range (flagged)
- Note: validate_date_range is informational, doesn't reject values

**9. test_format_fallback_order:**
- Test 4-format fallback order: DATETIME → DATE9 → YYYYMMDD → MM/DD/YYYY
- Cases:
  - "01JAN2020:14:30:00" → should match DATETIME first (not DATE9)
  - "01JAN2020" → should match DATE9 (DATETIME already tried, failed)
  - "20200101" → should match YYYYMMDD (previous formats failed)
